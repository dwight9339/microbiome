# Christmas 2026 Gift — Delivery Plan (draft)

**Target:** gift-ready by **Friday, December 18, 2026**, one week before Christmas (Friday, December 25). The week in between is contingency, not feature time.  
**Priority order:** working gift > dependable hardware > one distinctive world > the basic Studio that helps build it > engine delight > anything else.

One person builds this. The plan therefore starts the work that involves waiting (PCB fabrication, parts shipping, prints) first, and does software while those are in flight. **This file is the only place with dates;** the track roadmaps link here.

This is a tight six-week plan, not a promise that everything fits. Cut the stretch items early rather than late.

## Definition of done

**Must** — the gift is not ready without all of these:

1. **Hardware:** finished, safe, assembled devices on a **custom carrier PCB** holding an **RP2350 Feather**, in a **custom enclosure**, reusing the prototype TFT and buttons; RTC optional. Screen, buttons, power, USB and BOOTSEL access all usable. Decide how many gifts before ordering the PCB (board houses usually make at least five anyway). See the [Feather carrier plan](hardware/feather-carrier-2026.md).
2. **Firmware:** runs the gift world on that exact hardware with correct orientation, readable colours, responsive controls, reasonable frame rate and no crash over an extended soak.
3. **World:** one distinct, original world (not a reskin of forest) with finished art.
4. **Repeatable build:** the UF2, pack source, firmware version, board configuration and flash/recovery steps are archived. **Embedded pack in the UF2 is enough**; separate pack installation is not required.
5. **Gift readiness:** enclosure closed, wiring tidy with strain relief, USB/power reachable, restore/reflash path tested.

**Should** — pursue once the musts are on track:

6. **Basic Studio** (see [Studio track](roadmaps/studio.md)) used to build the gift world. Fallback if it isn't ready by the Nov 20 gate: build the world with YAML + `packc --watch` + `mbsim`, and finish Studio after Christmas.
7. **Living-world slice:** a bird moves perch → ground → perch **as the same actor**, with flight/landing/hopping animations, and a ground-only rabbit never picks the perch. If it threatens the musts, cut it to a smaller reachability-only slice and note what moved post-gift.

**Stretch:** a simple per-actor visual variant, one icy-patch stumble, extra polish.

**Not part of the gift:** production certification, a second LiPo charger (the Feather has one), a full Studio, Companion, independent `.mbp` install, a second MCU, generalised terrain or physics.

## Week by week

### Nov 5–13 — Hardware first; order the PCB
The PCB order is the one date that can't be won back later. Nothing else this week.
- Decide: exact Feather variant, TFT module and footprint, button count and layout, battery (chemistry, capacity, JST polarity), RTC yes/no, enclosure form factor, gift quantity.
- Draft the Feather pin map, wire it up temporarily, and get the firmware booting and drawing on the Feather (`PICO_BOARD=adafruit_feather_rp2350`).
- Check fab, parts and print turnaround times.
- Review the carrier schematic/layout against the [hardware checklist](hardware/feather-carrier-2026.md) and **order the PCB and parts by Nov 13**.
- Print a first enclosure fit mockup from the board dimensions; don't wait for the PCB.
- Pick the gift world's concept and visual style.

### Nov 14–20 — Basic Studio
- Build the [basic Studio](roadmaps/studio.md): dev server with rebuild and live reload, error banner, edit overlay with drag-to-move, comment-preserving save.
- **Gate (Nov 20):** dragging a place in the browser updates `pack.yaml` without losing comments, and the scene reloads. If not, fall back to YAML + `mbsim` for the world and move on.
- Track PCB/parts delivery.

### Nov 21–27 — Build the world
- Build the gift world with the basic Studio: layers, places, lanes, actors, spawns, art.
- Try the bird/rabbit slice only if the world is on track; otherwise defer it.
- Keep CI green and the forest pack working.

### Nov 28–Dec 4 — Bring-up
- Assemble the first carrier: USB-only, battery-only, charging with the TFT on, backlight current, all buttons, BOOTSEL/RESET, RTC if fitted.
- Run the gift world on the real hardware; check readability, frame rate, flash use, animations.
- Refine the enclosure against the real board.

### Dec 5–11 — Freeze
- Finish the art and pack; **feature freeze Dec 11**.
- Test flash/recovery, power cycling, charging/thermal behaviour, unplug/replug and long runtime.
- Print and assemble the final enclosures; archive the known-good UF2, pack, build commands and PCB/enclosure revisions.
- From here, a new idea has to replace something, not add to the list.

### Dec 12–18 — Burn-in and buffer
- Reflash the known-good image, burn in, and do hands-on checks on each assembled gift.
- Fix only critical defects. Write short setup/recovery notes to include with each gift.
- **Dec 18:** call it gift-ready only when every must passes.

## Risks and fallbacks

- **PCB delay:** using a Feather on a carrier, rather than a bare RP2350 design, keeps the board simple; order early. Develop software on temporary wiring until it arrives. Temporary wiring is a fallback for software, **not** a substitute for the custom PCB goal.
- **Studio slips:** fall back to YAML + `packc --watch` + `mbsim` at the Nov 20 gate. Don't grow it toward a behaviour graph, a desktop shell or browser-side compiling this season.
- **Navigation slips:** limit it to explicit ground/perch links and two locomotion modes in one demo, or cut it.
- **Parts or enclosure don't fit:** check connectors and fit on printed mockups; keep spare parts and time for a reprint.
- **Firmware slow or unstable:** keep the current tested renderer; lower actor/particle budgets for the gift world; profile on the real hardware before optimising.
- **Scope creep:** cut the bird slice, Studio extras and stretch items **before** relaxing any reliability test.
