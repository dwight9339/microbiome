# Christmas 2026 Gift — Integrated Delivery Plan (draft)

**Planning anchor:** Wednesday, November 4, 2026.  
**Target finished and gift-ready:** **Friday, December 18, 2026** (one week before Christmas, Friday December 25).  
**Non-negotiable ordering:** working gift > dependable hardware > one distinctive world > authoring workflow > optional engine delight > broader product features.

This is a **tight six-week plan**, not an estimate that everything below will definitely fit. Confirm fabrication/parts lead times, available hands/time, and manufacturing approach by **Nov 6**. Track blockers and cut stretch work quickly.

## Gift definition of done

All of the following must be demonstrated, on video and preferably with a witnessed physical check:

1. **Physical artifact:** at least one finished, safe, assembled device using a **custom PCB** and a **custom enclosure**; buttons, screen, power, USB/BOOTSEL access, and mounting are usable. A Pico 2 **carrier PCB** is the recommended custom PCB scope for this deadline (a bare RP2350 board may be too risky); confirm that this satisfies the intended gift by Nov 6.
2. **Software:** stable firmware runs a distinct, authored world on that exact hardware; correct screen orientation, readable colors, responsive controls, reasonable performance and no persistent crash over an extended soak.
3. **Studio:** creator can create/open a world folder, make essential *visual* changes to art/layers, a location, at least one actor or spawn rule, save the source files, compile with packc, and preview using the actual engine. Manual editing is allowed for advanced unsupported fields, not as a substitute for the whole authoring path.
4. **Living-world demonstration:** in the authored world, a bird can move from a perch to the ground and back **as the same actor**, using appropriate flight/landing/hopping animations; a ground-only rabbit cannot choose the elevated perch. A minimal explicit route/affordance model is acceptable. If this engine slice threatens hardware/world delivery, cut it to a smaller verified reachability/animation slice with the deviation explicitly recorded.
5. **Repeatable deployment:** build artifact, pack source, firmware version, board configuration, flashing/recovery steps, and a backup of the finished world are saved. **Embedded pack in UF2 is sufficient**; separate pack installation is not required.
6. **Gift readiness:** enclosure closed, practical wiring, strain relief, accessibility of power/USB and required controls, and a tested restore/reflash path.

**Not implied:** production certification, battery/charger design, a polished full Studio, marketplace, standalone Companion, independent .mbp download to flash, second MCU, or a generalized physics engine.

Do electronics, Studio, and engine work **in parallel**, not sequentially. Hardware H2/H3 are the longest-lead unknowns; do not wait for software to stabilize before ordering.

## Week-by-week decision gates

### Nov 4–6 — Choose and freeze direction
- Decide single gift target, approximate quantity (default one), board form factor, display, inputs, power source, whether optional RTC is included, and whether **Pico 2 carrier PCB** counts as the custom PCB deliverable.
- Lock the intended world concept, visual style, display resolution and Studio minimum edit operations.
- Confirm fab, parts, and 3D-print turnaround; assign responsibility and explicit backup paths.
- Create a risk board with testable deliverables; reserve the last week for stabilization.

### Nov 7–13 — Prove the basic loop; release PCB
- Validate current reference hardware, firmware boot and known-good flash.
- Verify a custom pack -> packc -> live preview (Wasm or SDL) -> UF2 -> reference display.
- Complete schematic/layout peer review, order PCB and critical components **by Nov 13** if lead times allow; check USB/BOOTSEL access, connector orientation, power and display pinouts.
- Print enclosure fit prototype using final board dimensions; do not wait for completed PCB.
- Studio opens an existing pack and offers at least one actual visual edit; prototype reachable affordances and bird transition without committing to full navigation rewrite.

### Nov 14–20 — Minimum working vertical slices
- Studio folder open/save with preserved assets; create/edit a place and layer; compile and refresh preview, with clear errors.
- Engine proof: perched bird -> fly -> ground hopping -> fly -> perch as one actor; rabbit not offered unreachable perch.
- Verify distinct contextual animations; add deterministic scenario/test seed to replay transition.
- Review enclosure ergonomics and PCB/parts delivery status; update contingency.

### Nov 21–27 — Complete authoring path and integration
- Studio edits an actor/spawn rule and enough content settings to construct the chosen world; source files remain usable from packc/CLI.
- Compile, preview, run and save a **distinct** gift world; demonstrate without relying on manual edits for all essential fields.
- Merge engine vertical slice or explicitly reduce it if late; retain CI and old pack behavior.
- Prepare final firmware build, documentation and manufacturing checklist.

### Nov 28–Dec 4 — Device/world integration
- First custom PCB electrical bring-up and final enclosure fitting as parts become available; test power, display, buttons, USB/BOOTSEL and RTC if included.
- World runs on target hardware; check scene readability, performance, memory/flash, animation and transitions.
- Fix usability blockers and replace placeholder art in the gift scene; identify only defects that still block completion.

### Dec 5–11 — Feature freeze and acceptance
- Finish artwork and pack, freeze features by **Dec 11**.
- Test full flash/recovery, power cycling, controls, clock, unexpected unplug/replug and extended runtime. Ensure no corrupted or unbootable result.
- Print final enclosure; label, assemble, confirm PCB fit; archive known-good firmware/world, build commands and source.
- Any new feature request must replace another item, not add to the gift scope.

### Dec 12–18 — Buffer, burn-in, handoff
- Reflash known-good image; perform final burn-in and hands-on checks on the assembled gift hardware.
- Fix only critical defects. Package the device with straightforward setup/recovery instructions.
- By **Friday Dec 18**, declare gift-ready only when all must-have checks pass; preserve the week until Dec 25 as contingency.

## Must / should / stretch / later

| Category | Includes |
| --- | --- |
| **Must** | Proven firmware and custom board + enclosure; one new world via Studio's minimum UI; pack compile/preview/save; good hardware boot/flash; documentation and recovery |
| **Should** | Visible bird ground/perch traversal preserving identity, species-specific reachability, automatic context animations; simple deterministic scenario testing |
| **Stretch** | A small actor visual variant, one simple icy slip, extra polish, more complete visual editors, custom board bare-chip integration |
| **Later** | Fully procedural actor generation, generic 3D/depth planes, elaborate terrain physics, persistent actor history, all-feature Studio, Companion application, independent pack flashing, second hardware port, account/community platform |

**Priority nuance:** the bird/rabbit demonstration is the preferred engine feature target and should be actively pursued. It must **not** delay completion of the PCB, enclosure, new world or working firmware. If a cut occurs, record what was demonstrated and what moved post-gift.

## Risks, cut lines and fallback

- **PCB delay:** pick a Pico 2 carrier over a from-scratch RP2350 schematic; place the order early. Use the proven reference wiring for software until PCB arrives; if final PCB cannot arrive, escalate immediately—reference wiring is a delivery contingency, **not** evidence that the custom PCB goal was met.
- **Studio slips:** shrink editors to import art, layers, place positions, basic actor/spawn controls, save and rebuild. Keep a clearly marked advanced YAML mode for unsupported options. Do not expand to a behavior graph or Pyodide web authoring this season.
- **Navigation redesign slips:** limit to explicit ground/perch connections and two locomotion modes in one demo. Defer generalized terrain graph and dynamic conditions.
- **Parts/enclosure fail:** test critical connectors and fit on printed mockups; retain duplicate components and reprint time.
- **Slow or unstable firmware:** keep current tested rendering path, reduce actor/particle budget for the gift world, profile on actual hardware before optimizing.
- **Scope creep:** cut marketplace/Companion, independent pack installs, full actor generation, slipping and extended terrain mechanics **before** relaxing reliability or gift-completion tests.
